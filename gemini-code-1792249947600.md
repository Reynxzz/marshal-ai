# Marshal on Three.js & TanStack Start: A Pure TypeScript Replacement for CARLA

Dokumen ini menjelaskan spesifikasi teknis untuk membangun **Marshal** dan simulator pabriknya secara utuh di dalam ekosistem **TanStack Start (Fullstack TypeScript)** dan **Three.js**, menggantikan ketergantungan pada simulator CARLA (GPU VM) maupun *backend service* Python.

**Tujuan Utama:** Membangun dunia 3D ("plant") berbasis Three.js dan mesin orkestrasi Marshal menggunakan TanStack Start (React + Server Functions) sehingga seluruh alur *demo* dapat berjalan langsung di browser tanpa *service* Python terpisah:

- Gate check (inspeksi visual gerbang)
- Lamp check (inspeksi lampu & deteksi *fault*)
- Route choice (pemilihan rute dinamis saat ada bahaya)
- Gemini parking (parkir otonom berbasis *vision/diagram* Gemini)
- Yard re-plan (penataan ulang slot parkir saat truk terlambat)
- Blocked car asking for help (intervensi manusia & Gemini saat jalur terhalang)

**Bukan Tujuan:** Fotorealisme atau akurasi fisika tingkat tinggi. Bar ukurannya sederhana: Gemini harus bisa *membaca* setiap *frame* kamera (warna mobil, lampu menyala atau mati, kotak atau pekerja di jalur), dan mobil dapat bergerak secara meyakinkan pada kecepatan jalan kaki.

## 1. Bagaimana Marshal Berkomunikasi dengan Simulator (The Contract)

Marshal tidak pernah mengemudikan kemudi mobil secara langsung di level *flow* utama; ia mengirimkan **misi (missions)**, lalu sistem pengemudi (*driving system*) di Three.js menjalankannya dan melaporkan statusnya kembali. Kontrak ini didefinisikan sebagai *TypeScript Interface* (`DrivingSystem` di `src/lib/marshal/driving/api.ts`) dengan tipe pesan di `src/lib/marshal/driving/messages.ts`.

### Marshal Orchestrator → Three.js Simulator (Commands)

| Message / Action | Fields | Arti / Perilaku |
|---|---|---|
| `mission.go` | `mission_id, vin, waypoints[], max_speed_kmh=10, routine?, routine_steps?` | Kemudikan mobil melewati titik-titik peta (*named points*) secara berurutan. Jika `routine` (misal `"R-12"`) diisi, jalankan rutinitas pengujian saat mencapai `test_track`. |
| `mission.hold` | `vin, duration_s?, reason` | Berhenti dan tetap diam (sampai ada `mission.resume`, atau selama `duration_s`). |
| `mission.resume` | `vin` | Lanjutkan perjalanan setelah status *hold*. |
| `assist.choose` | `case_id, vin, option, chosen_by` | Operator manusia memilih salah satu opsi tindakan yang ditawarkan mobil saat meminta bantuan. |

### Three.js Simulator → Marshal Orchestrator (Events)

| Event | Fields | Kapan Dikirim |
|---|---|---|
| `status` | `vin, location, x, y, speed_kmh, mission_id, progress, held, stopped_for_assist` | Setiap mobil, **satu kali per detik simulasi (1 Hz)**. `location` adalah titik peta terakhir yang dilewati. |
| `mission.done` | `mission_id, vin, location` | Mobil telah mencapai *waypoint* terakhir pada misinya. |
| `track.step` | `vin, mission_id, routine, step, name, telemetry{}` | Satu langkah rutinitas selesai di `test_track`, beserta data yang dilaporkan oleh sistem elektronik mobil. |
| `assist.request` | `case_id, vin, location, reason, options[], clip_frames[]` | Mobil berhenti karena ada sesuatu yang menghalangi jalur, dan meminta keputusan manusia. |

Secara desain, **tidak ada** perintah untuk membelokkan setir secara manual dari luar pada mode jelajah biasa, atau mengabaikan penghentian darurat (*safety stops*) milik mobil itu sendiri.

### Method Tambahan pada Engine Simulator (`ThreeJsBackend`)

Selain protokol pesan di atas, *flow* skenario dan komponen UI Dashboard memanggil beberapa *method* dan *state* langsung pada *instance* simulator (`src/lib/simulator/engine.ts`):

| Method / State | Kegunaan |
|---|---|
| `spawn(vin, { at, colour, behind_m })` | Menempatkan mobil di peta; `behind_m` mengantrekan mobil ke belakang mengikuti arah *heading* titik tersebut. |
| `despawn(vin)` | Menghapus mobil beserta kamera *onboard*-nya dari *scene*. |
| `faults.set(vin, new Set(["headlights"]))` | Simulasi "bohlam mati": mobil **melaporkan** lampu `ON` pada telemetri, namun secara visual tetap **gelap** di kamera. |
| `repair(vin, defect_types)` | Bengkel (*rework*) memperbaiki mobil (menghapus *fault*). |
| `getTransform(point)` / `getPositionXY(vin)` | Mengambil koordinat titik peta atau posisi mobil saat ini. |
| `getAssistMedia(case_id)` | Mengambil kumpulan *frame* (base64 JPEG) sebelum mobil berhenti untuk dianalisis Gemini dan ditampilkan di UI Dashboard. |
| `raiseAssist(vin, case_id, reason, options)` | Memaksa permintaan bantuan muncul (untuk skenario *scripted*). |
| `passes[vin]` | Mencatat kecepatan (km/j) tepat saat mobil melintasi gerbang (untuk klaim "drive-through at 5 km/h"). |
| `assistOutcomes[case_id]` | Mencatat hasil eksekusi dari opsi bantuan yang dipilih (menunggu N detik, lewat di 3 km/j dengan jarak bebas X meter, kontak/benturan). |
| `parkingLog[vin]` | Riwayat sesi parkir Gemini (keputusan per langkah, hasil akhir, pose akhir). |
| `storeArtifact(uri, blob)` | Menyimpan *frame* bukti ke penyimpanan (lokal / IndexedDB / Cloud Storage via Server Function). |

Terdapat juga dua pengelola kamera: `GateCamera.capture(vin, views)` dan `TrackCamera.getClip(vin, step, name)` (lihat §5).

## 2. Arsitektur TanStack Start (Tanpa Python)

Karena seluruh aplikasi berjalan di atas **TanStack Start**, kita tidak lagi memerlukan jembatan WebSocket ke proses Python eksternal. *Simulation Loop*, *State Management*, dan *UI Dashboard* berjalan menyatu di sisi *client*, sementara pemanggilan **Gemini API (`@google/genai`)** dieksekusi dengan aman melalui **TanStack Server Functions (`createServerFn`)**.

```text
 ┌──────────────────── TanStack Start Application ────────────────────┐
 │                                                                    │
 │  ┌─────────────────── Client (Browser Runtime) ─────────────────┐  │
 │  │                                                              │  │
 │  │  [React Dashboard UI] ◄──► [Marshal State & Flows (TS)]      │  │
 │  │   (TanStack Router/Store)   (gate, lamp, route, yard, etc.)  │  │
 │  │                                     │                        │  │
 │  │                        In-Memory Method & Event Bus          │  │
 │  │                                     ▼                        │  │
 │  │                            [Three.js Plant Engine]           │  │
 │  │                             (world, cars, cameras,           │  │
 │  │                              kinematics, WebGLRenderTarget)  │  │
 │  └─────────────────────────────────────┬────────────────────────┘  │
 │                                        │                           │
 │                         RPC (createServerFn / HTTP)                │
 │                                        ▼                           │
 │  ┌─────────────────── Server (Node / Edge / Bun) ───────────────┐  │
 │  │  [TanStack Server Functions]                                 │  │
 │  │   • evaluateGatePhotos()      ──► @google/genai (Gemini)     │  │
 │  │   • evaluateLampEvidence()    ──► @google/genai (Gemini)     │  │

 │  └──────────────────────────────────────────────────────────────┘  │
 └────────────────────────────────────────────────────────────────────┘
